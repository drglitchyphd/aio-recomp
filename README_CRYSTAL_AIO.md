# Crystal-AiO (mod id `crystal-aio`)

One mod for Pokemon Crystal on Gen1Recomp. Until 1.0.0 it was called
**Gen2-AIO** (mod id `gen2-aio`); its settings are imported on first launch.

- **Features:** [FEATURES.md](FEATURES.md) is a tour of everything the bundle
  does and where to find it in the CRYSTAL-AIO menus.
- **Credits:** [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) credits every
  bundled mod, artist and asset source. [ASSET_NOTICES.md](ASSET_NOTICES.md)
  covers the art in more detail.

## Installing and updating

In Gen1Recomp's launcher, open **MODS -> Find mods**, open its index/source
management, and add this custom index URL:

```text
https://raw.githubusercontent.com/drglitchyphd/aio-recomp/main/site/data/index.json
```

Select **Crystal-AiO** to install it. The launcher uses this repository for
**Update** and **Versions**. No GitHub Pages setup is required.

For maintainers: commit all runtime folders (including the restored release
assets), the index, tools and `.github/workflows` before releasing. Update
`manifest.json` and these notes (a `## X.Y.Z changes` section). Merging that
version bump into `main` runs **Auto release on version bump**, which publishes
the matching tag (e.g. **v1.0.1**) with that section as its notes; publishing a
release by hand on GitHub still works too. **Package mod release** builds and
attaches `crystal-aio-<version>.zip` and checksums, plus an overlay patch
(`crystal-aio_patch_<old>_to_<new>.zip`) against the newest older
`crystal-aio` release; then **Refresh mod index** commits the new listing to
the default branch. The index also refreshes daily and can be run manually from
Actions. Workflows need permission to write repository contents; branch rules
must permit the bot's index commit. Check both jobs are green after publishing.

An overlay patch cannot delete files. A release that removes files must be a
**full-install release** (full ZIP only): a new major version (like 1.0.0) is
one automatically, and the first release of a mod id is one too. Otherwise the
packager stops with "overlay patch cannot delete files" -- bump the major
version, or build it locally with `--full-install`.

To build locally:

```sh
python3 tools/build_release.py --tag v1.0.1 --previous-zip /path/to/crystal-aio-1.0.0.zip
python3 tools/build_release.py --tag v1.0.0 --full-install    # full ZIP only
```

Outputs go to `dist/`. Upload the canonical `crystal-aio-<version>.zip`
alongside any patch so the launcher selects the complete build. Source ZIPs
generated by GitHub and overlay patches are not the updater's install package.
The custom index is independent of the community index; a community listing
would require a separate submission.

## 0.9.85 changes

- BUILD 3D CACHE now helps in the same session, not only after a restart.
  Building every area made the game unpack every building model in the
  game and keep them all in memory (the same ~600 MB that 0.9.84 removed
  at start-up). Models are no longer kept once built into an area, and
  the build frees what it used as it goes and when it finishes.
- When the build finishes, the page says so and recommends a restart:
  save, then close and reopen the game. The game cannot restart itself.

## 0.9.84 changes

- 3D world: much faster and lighter.
  - The 3D building data (every building model for every tileset) was
    unpacked in full when the 3D world started. That meant about 17 million
    small Lua objects, about 600 MB of memory, and seconds of loading.
  - The game then kept walking all of that memory for the rest of the
    session, which slowed every area build and caused hitches.
  - Building models are now unpacked one at a time, the first time a map
    uses them. The data loads in about 0.1 s and takes about 30 MB.
  - In testing, a route that took 19 s to build now takes under 1 s, and
    the longest freeze dropped from 10 s to 0.2 s.
- VOXEL DISK CACHE now works on phones and tablets. Once an area is built
  in 3D, later visits and restarts load it from storage instead of
  rebuilding it. BUILD 3D CACHE in GEN2-AIO > ADVANCED is available there
  too. Old cache files are cleared automatically.
- DIAGNOSTICS `voxel slow` now lists the three biggest steps of a long
  build step.

## 0.9.80 changes

- 3D world: the VOXEL DISK CACHE could switch itself off without a word.
  If its background writer failed to start, the first area lookup threw,
  and from then on every area rebuilt from scratch on every visit. This is
  the likely cause of the multi-second slowdowns walking in and out of
  buildings (0 areas loaded from disk). A failed start now just turns the
  cache off.
- DIAGNOSTICS always shows a `disk cache` line, including OFF and the
  reason (the setting, or why the writer could not start).
- Updates that only touch diagnostics or build scheduling no longer
  throw away your saved 3D areas.

## 0.9.79 changes

- 3D world: fewer long freezes while an area builds in the background.
  This was most noticeable walking out of houses in Azalea Town while Ilex
  Forest built. Dense forest cells are expensive, and the builder only
  checked the clock every 32 steps, so one slice could run 130 ms over.
  It now checks every 4 steps.
- DIAGNOSTICS `voxel slow` now names the step a long slice was spent in
  (structures, cells, trees, upload, persist ...). A new `voxel slow worst`
  line keeps the longest one.

## 0.9.78 changes

- DIAGNOSTICS now shows where a slow area's time goes, on two new lines:
  - `voxel frame`: the 3D world's update and draw times (average / peak
    over the last second), draw calls, shader and canvas switches, and
    texture memory.
  - `voxel churn`: how many characters the area is running, mesh rebuilds
    in the last second (and which map asked), builds so far (and how many
    came from the disk cache), and builds still queued.
  This is for tracking down slowdown in specific areas such as Azalea
  Town; nothing changes with DIAGNOSTICS off.

## 0.9.12 changes

- **VOXEL DISK CACHE** (gmarc, default ON). Every voxel map that finishes
  building is saved to storage (LZ4-compressed, by a background thread) and
  restored from there from then on -- this session and every later one. A
  restore is a file read plus a budgeted GPU upload instead of a full rebuild
  (structures, geometry, trees, grass, cuttable trees, support heights).
  Nearby maps and door destinations keep being prepared as you move, as
  before, and are saved too. The cache key covers the map's live block
  layout, its neighbours, its tileset and Crystal's VOID FILL, so an edited
  map (a cut tree, a moved boulder) simply gets its own file. Files are kept
  across bundle updates unless the voxel builder itself changed.
  - Storage: up to roughly 0.5-2 GB if you visit everything.
  - Needs the `compute` permission (a background thread); the engine may ask.

## Integration notes

- Wilds and Nuzlocke keep their settings / save data under `wok_` and `nz_`
  key prefixes, so generic names never collide with KIM's. Settings from the
  separate copies of these mods do not carry over.
- Wilds sees gmarc as a Dramatic Shape-family engine and uses its
  variable-size voxel adapter; under BATTLE ART it uses its Battle Art adapter.
- Nuzlocke's Gold-only checks now accept the whole GSC family. Its Gold beta
  rule set applies to Crystal; maps Crystal adds may need runtime checks.
- The empty native battle text box (intro, between lines) is hidden when KIM's
  Modern UI is on; prompts, move learning and the level-up stats box stay.
- Every change to bundled code is marked `KIM_ARENA` in the source.
